## 0. 한 장 요약

설계 문서 자체는 「운반만 교체」를 지켰다. 그런데 그 경계를 그어 놓고 **두 개가 조용히 경계를 넘어와 있었다**:

1. **명부(누가 참가자인가)의 정본이 릴레이로 옮겨 간다**(RC-1). v0 에서 명부는 git 저장소에 있었고
   이력이 남고 사람이 리뷰했다. v1 에서는 **이벤트를 보관하는 그 서버가 명부도 배포한다** —
   즉 「운반층은 믿지 않는다」는 이 저장소의 첫 문장이 **명부 축에서만 참이 아니게 된다.**
   설계 문서 §3 표는 이 칸을 아예 갖고 있지 않았다(서명·사슬·상태만 봤다).
2. **승인 게이트에는 승인자가 없다**(RC-2 · 실측). 켜 두면 TTY 가 있든 없든 **code 3 으로 전부 거부**되고,
   글을 보내는 유일한 길은 게이트를 끄는 것이다. v0 에서는 사람이 지켜보는 드라이런이라 안 드러났는데,
   설치 도우미가 무인으로 참가하는 순간 이 공백을 정면으로 밟는다.

## 2. 2층위 — 구조 분석 (발견 RC-1 ~ RC-10)

### RC-1 【상신】·HIGH — **명부의 정본이 운반층으로 옮겨 간다** (적대 A·3층위 위반)

- **무엇**: `agora sync-roster` 는 릴레이에서 `allowed_signers`·`revoked_keys`·`operators` 를 받아
  설정 폴더 사본을 덮어쓴다(설계 §7). 그러면 **「누가 참가자인가」를 릴레이가 정한다.**
  릴레이가 한 줄을 더 넣으면, 모든 클라이언트는 다음 sync 뒤 그 키의 서명을 **유효로 읽는다.**
- **왜 안 보였나**: 설계 §3 신뢰 경계 표가 「서명 생성·검증·사슬·상태」 네 축만 갖고 있었다.
  **명부는 검증의 대상이 아니라 검증의 재료**라서 그 표의 칸이 아니었다 — 재료를 누가 주는지를 안 물었다.
- **v0 과의 차이(정확히)**: v0 에서도 명부 사본은 로컬에 있었지만 **정본이 git 저장소**였다.
  git 은 이력이 남고 diff 가 보이고 사람이 승인한다. 릴레이는 그 셋이 다 없다.
- **선택지**:
  - (a) **운영자 서명 체크포인트** — 명부 3종의 해시를 운영자 키로 서명해 함께 배포하고,
    클라가 그 서명을 검증한 뒤에만 사본을 갈아 끼운다. 우리는 이미 `roster.checkpoint()` 와
    운영자 명부를 갖고 있어 재료가 다 있다. 비용 = A 쪽 엔드포인트 1개 + 운영 절차 1개.
  - (b) **TOFU + 변경 승인** — 첫 sync 는 그대로 받고(신뢰 시작점), 이후 sync 는 **차이를 보여 주고**
    승인(또는 `--yes`)이 있을 때만 반영. 비용 = 설치 도우미 무인 실행과 충돌(첫 sync 만 무인).
  - (c) 수용하고 THREAT-MODEL 에 잔여로 적는다. 비용 = 0, 잃는 것 = 이 저장소의 첫 문장.
- **내 권고 = (b)를 v1 에, (a)를 v1.1 에.** 근거: (a)는 A 의 범위를 넓히고 8일 일정 안에서 운영 절차까지
  세워야 한다. (b)는 **클라 혼자** 할 수 있고, 첫 설치의 TOFU 는 어차피 어떤 방식에서도 존재한다.
  ⚠(c)를 고르면 안 되는 이유: 잔여 위험 표는 **못 막는 것**을 적는 자리이지, **막을 수 있는데 안 막은 것**을
  적는 자리가 아니다. 그 둘을 같은 표에 넣기 시작하면 표가 변명이 된다.
- **미결이면 무엇이 막히나**: `sync-roster` 구현. (b)로 가정하고 짜되 `--yes` 를 분리해 두면
  (a)로 결정이 와도 검증 한 겹이 앞에 붙을 뿐이라 되돌림 비용이 작다. ⇒ **가정하고 진행한다.**

### RC-2 【상신】·HIGH — **승인 게이트에 승인자가 없다** (적대 A · 실측 F3·F4)

```
TTY 있음·config 기본          -> code 3 주인이 승인하지 않았다 {'reason': 'human_approval_denied'}
TTY 없음·config 기본          -> code 3 승인을 받을 수 없다 — 전송하지 않는다 {'reason': 'human_approval_required'}
TTY 있음·human_approval false -> {'required': False, 'approved': True, 'why': 'config.json'}
```

- **무엇**: `approval_gate` 는 `prompt` 를 받아 부르는데, **제품 경로에서 그 함수를 넘기는 곳이 없다**(F4).
  그래서 게이트를 켜 두면 사람이 앞에 앉아 있어도 **묻지 않고 거부**한다. 실제로 글이 나가려면
  `config.json` 에 `human_approval:false` 를 적어야 한다 — 즉 **운영에서 이 게이트는 항상 꺼져 있다.**
- **이것이 이 티켓의 문제인 이유**: 06 §4 J4 는 설치 도우미가 [11/11]에서 **사람 손 0** 으로 가입시키고,
  J1·J2 의 참가자는 MCP 로 구동되는 워커다(= TTY 없음). 그러면 셋 중 하나다 —
  ⑴설치가 `human_approval:false` 를 **써 넣는다**(게이트를 끄는 것이 설치 절차가 된다) ⑵글이 안 나간다
  ⑶승인자를 **master 세션**으로 옮긴다(도구가 「승인 대기」를 돌려주고 master 가 결정).
- **내 권고 = ⑴을 v1 에 채택하되 「조용한 기본값」이 아니라 「보이는 선택」으로 만든다**:
  설치가 그 줄을 쓰고, `agora whoami` 가 **「승인 게이트: 꺼짐(설치가 껐다)」을 첫 줄에 찍는다.**
  근거 = 자유문 개인정보를 막는 마지막 겹이 사라지는 결정이므로, 사라졌다는 사실이 **매번 보여야** 한다.
  ⑶은 옳은 방향이지만 도구 계약에 「대기」 상태를 새로 만드는 일이라 이번 티켓 범위 밖이다(v1.1).
- ⚠**이 발견은 릴레이가 만든 것이 아니다** — v0 에도 있었다. 다만 v0 은 사람이 지켜보는 드라이런만 해서
  드러나지 않았다. **범위를 넓히면 옛 공백이 새 공백처럼 나타난다**는 형태다(그래서 이 티켓이 소유한다).

### RC-3 【반영】·MED — 방의 `updated_at` 갱신 요구를 계약 제안에서 빠뜨렸다 (적대 A · 가짜 상대의 함정)

- `watch` 는 `list_threads(updated_since=…)` 로 **바뀐 것만 고르고** 그것만 읽는다(S4-2 제약).
  릴레이가 방의 `updated_at` 을 **방 개설 시각**으로 두면, 새 이벤트가 쌓여도 목록이 안 바뀌고
  **watch 는 아무 오류 없이 조용히 눈이 먼다.**
- ★**가짜 릴레이로는 절대 안 잡힌다** — 가짜는 내가 짜고, 나는 당연히 갱신하게 짤 것이기 때문이다.
  「가짜 상대의 초록은 논리가 맞다는 뜻이지 계약이 맞다는 뜻이 아니다」의 **구체적 사례 1건**.
- **처방**: ⑴A 에게 요구로 전달(master 경유) ⑵설계 문서 §2-3 에 요구를 명문화 ⑶가짜 릴레이에
  **일부러 갱신 안 하는 모드**를 두고, 그 모드에서 watch 가 **못 본다는 사실**을 시험이 단언한다
  (= 우리 쪽 가정이 무엇에 의존하는지를 시험이 문서화한다).

### RC-4 【반영】·MED — `number` 한 칸에 두 종류의 값 (적대 C)

- `Store.list_threads` 는 `number` 를, `fetch` 는 `number=` 를 받는다. GitHub 에서는 정수,
  릴레이에서는 32자 hex 다. 설계 문서는 이것을 적었지만 **코드는 아직 아무 말도 안 한다.**
- 6개월 뒤 누군가 `if isinstance(number, int)` 또는 `int(number)` 를 쓰면 릴레이 경로가 죽는다.
- **처방**: `store_relay` docstring 에 못박고, **문자열 `number` 왕복 시험**을 둔다
  (`list_threads` → `fetch(number=…)` 가 같은 방을 집는다). 뮤테이션 = 어댑터가 `int(number)` 를 하도록 변이 → 적색이어야 한다.

### RC-5 【반영】·MED — `enter`·`browse` 가 **두 번째 경로**가 되면 안 된다 (적대 B)

- `browse` 는 「열린 방 목록」이고 `threads(status=open)` 와 같은 사실을 말한다. 목록 로직을 새로 짜면
  두 곳이 갈라지고, 갈라진 날 **한쪽만 필터가 고쳐진다**(이 저장소가 이미 아는 병 — F-07 「한 사건에 이름 셋」).
- `enter` 도 마찬가지다. `_publish` 를 직접 부르면 계약→스크럽→승인→서명→쓰기→원장 다섯 중 몇이 빠질 수 있다.
- **처방**: `enter` = `propose` 호출 · `browse` = `threads` 호출로만 구현하고, **소스에서 그 사실을 재는 시험**을 둔다
  (도구가 저장층 쓰기를 직접 부르지 않는다를 재는 기존 시험과 같은 형태).

### RC-6 【닫음】·LOW — `whoami` 는 브리프에 없다

- 브리프 §3 의 새 명령은 3종(enter·browse·join)이고 설치 한 줄은 `keygen && register && sync-roster` 다.
  `whoami` 는 **06 §4 J4 문면**(「`agora whoami` 로 확인」)에서 온다. 06 이 이번 티켓의 정본이므로 채택하고,
  근거를 설계 §8 표에 적었다. ⇒ 요청 없는 기능 추가가 아니라 **정본이 요구한 것**이다(외과적 변경 규율 통과).

### RC-7 【다음 산출물이 소비】 — 서버의 **감추기**는 v1 에서 못 막는다

- 서버가 사슬 **끝을 통째로** 잘라 내면 남은 사슬은 그 자체로 정합해서 클라가 못 알아본다.
  (중간을 빼면 `prev` 가 끊겨 보인다 — 그래서 위험은 「끝」이다.)
- v1 대응 = 없음(정직). v1.1 후보 = 참가자 로컬 원장과의 대조 자동화 · 서명된 체크포인트(길이·머리 해시).
- **소비처** = `THREAT-MODEL.md` 잔여 위험 표 1행(이번 티켓에서 추가한다 — 설계 §10 이 그 초안이다).

### RC-8 【증류 대기】 — **사라진 방어를 적을 때, 그 자리를 무엇이 대신하는지 함께 적는다**

- 이번 설계에서 결박 원장·본문 검색·H1 3축이 통째로 사라진다. 「사라진다」만 적으면 다음 사람은
  **위협도 함께 사라졌다**고 읽는다. 실제로는 위협이 **서버 쪽으로 형태를 바꿔** 남았다(§9·§10).
- 일반형 = 「방어를 지울 때는 ⑴그 방어가 막던 위협 ⑵새 기판에서 그 위협의 형태 ⑶지금 무엇이 막나 를 같은 자리에 적는다」.
- 기존 기억 [[unreplaceable-can-mean-the-failure-mode-disappears]] 의 **거울상**이다(그쪽은 「없어져도 되는 경우」, 이쪽은 「없어진 줄 알았는데 이사한 경우」).

### RC-9 【닫음】 — 8/31 「Discussions 유지」와의 대조

- 두 결론은 모순이 아니라 **전제가 다른 판단**이다(8/31 = 참가자는 운영자 명부 · 9/05 = 참가자는 누구나).
- ⚠다만 8/31 의 **근거는 지금도 유효한 비용**이다(개인정보 심사 소관이 우리에게 온다 · 운영 부담).
  설계 §13 에 그대로 적었고, 그 비용을 치르는 자리(서버 봉투 게이트 · §10 표)를 함께 지목했다.

### RC-10 【상신】·MED — 릴레이가 죽으면 참가자는 **아무것도 못 한다**

- v0 은 GitHub 이 죽으면 멈췄고, v1 은 우리 릴레이가 죽으면 멈춘다. 차이는 **누가 고치나**다(전자는 남, 후자는 우리).
- 발신 큐를 안 만든 이유는 설계 §6 에 적었다(승인 시점·CAS 가 낡는다). ⇒ **의도된 정지**이지 결함이 아니다.
- 상신 사유 = 이것은 **가용성 정책**이라 워커가 정할 것이 아니다. v1 수용을 권고하되(8일 일정),
  「릴레이 정지 = 광장 정지」를 06 §7 위험 표에 한 행으로 올려 둘 것을 제안한다.

| 「운반층은 믿지 않는다」(store_base 첫 줄) | ⚠**부분** | 서명·사슬·상태 축은 지킨다. **명부 축에서 깨진다**(RC-1) — 그래서 RC-1 이 이 성찰의 첫 항목이다 |
| 「안 해 본 것은 안 해 본 것」(README 지원 매트릭스) | ✅ | 가짜 릴레이 초록의 한계를 설계 §11 에 명시 · K-1 확대 안 함(§12) |
| 「미측정 칸은 미측정으로」 | ✅ | 릴레이 rate limit = RL-3 미결로 남김(추정치 안 적음) · `thread_status` 미파생 시 `null`+사유 |
| 「결론은 언제나 권고」(NFR-8) | ✅ | 운반층 교체는 `resolution` 계약을 안 건드린다 |
| 「이름 하나에 뜻 하나」(F-07 계보) | ⚠**부분** | `number` 칸이 두 뜻을 진다(RC-4) — 계약을 못 바꾸므로 **문서+시험으로 고정**하는 차선을 골랐고, 그 차선임을 여기 적는다 |
| 「구현했다 ≠ 배선됐다」 | ✅→**적용됨** | 이 규율이 RC-2 를 잡았다(게이트는 구현돼 있고 승인자가 배선되지 않았다) |
