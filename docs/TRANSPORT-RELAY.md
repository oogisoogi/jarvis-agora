# TRANSPORT-RELAY — 릴레이 운반층 (클라이언트 어댑터 설계 v1)

> 정본 = `.appbuild/06-fair-v1-user-journey-prd-addendum.md`(발주자 결정 2026-09-05).
> 이 문서는 **클라이언트 쪽 설계**다. 서버(릴레이) 쪽 계약의 정본은 워커 A 의 `docs/RELAY.md` 이고,
> 여기 적힌 요청·응답 모양은 **클라가 필요로 하는 최소 형태**로서 A 에게 제안된 것이다(2026-09-05 21:58 인박스).
> 두 문서가 갈리면 **A 의 RELAY.md 가 이긴다** — 그때 고치는 것은 이 문서와 `store_relay.py` 다.

## 0. 한 문장

**운반층만 갈아 끼운다.** 서명·사슬·상태 계산·봉투·스크럽·승인 게이트는 **하나도 옮기지 않는다** —
그것들은 전부 클라이언트에 남고, 릴레이는 「글을 받아 두고 돌려주는 곳」이다.

## 1. 무엇이 바뀌고 무엇이 안 바뀌는가

| 층 | GitHub Discussions(v0) | 릴레이(v1) | 바뀌나 |
|---|---|---|---|
| 주소 | 저장소 + Discussion **번호** | 릴레이 URL + **방 id = 우리 thread_id** | ✅바뀐다 |
| 전송 수단 | `gh` CLI subprocess(GraphQL) | `urllib.request`(표준 라이브러리 HTTPS) | ✅바뀐다 |
| 게시물 본문 | 표식 주석 + json 펜스 + 서명 블록 | **같다**(글자 하나 안 바꾼다) | ⛔안 바뀐다 |
| 서명·검증 | 클라 `ssh-keygen -Y` | **클라 그대로** + 서버가 한 번 더(백스톱) | ⛔클라 쪽은 안 바뀐다 |
| 상태 계산 | 클라 reducer | **클라 reducer 그대로** | ⛔안 바뀐다 |
| 오류 계약 | code 2·3·4·5·7·8·9·10 | **같은 코드**(매핑만 새로 · §5) | ⛔안 바뀐다 |
| 스레드↔운반 주소 결박 | `thread-bindings.json` + 본문 검색 | **불필요**(주소가 곧 이름) | ✅사라진다(§9) |
| 화면 투영(`project`) | 닫기·answer 표시 | **없음**(보드가 이벤트에서 파생) | ✅없어진다(§2-5) |

⛔ 불가침(06 §2): 개인정보·비밀 유출 0(봉투 게이트 유지) · 결론은 언제나 권고 ·
**서명 없는 이벤트는 존재하지 않는 것으로 취급**.

## 2. 어댑터 인터페이스 — `agora/store_relay.py`

`store_base.Store` 의 6함수를 **그대로** 구현한다. 도구·코어·reducer 는 한 줄도 안 고친다.
전송 자리는 **한 곳**(`relay_transport`)으로 모은다 — `store_github.gh_transport` 와 같은 이유다:
⑴논리를 네트워크 없이 시험할 수 있고 ⑵재시도·backoff 를 한 곳에서 건다.

### 2-1. `append(thread_id, category, title, body, is_genesis) -> {node_id, url, created_at}`

```
POST {relay}/events
{"thread_id": "<32hex>", "category": "debate|problem|knowhow",
 "title": "<genesis 일 때만 의미>", "body": "<렌더된 게시물 원문 그대로>", "is_genesis": true|false}
→ 201 {"event_id": "...", "url": "...", "created_at": "2026-09-05T12:00:00Z"}
```

- `event_id` → 우리 `node_id`. 이름이 다른 이유는 서버가 GitHub 이 아니기 때문이고, **이름을 맞춰
  주는 자리는 어댑터 안 한 줄**이다(그 한 줄이 이 파일의 존재 이유다).
- ★**멱등을 서버에 요구한다**: 같은 `message_id`(본문 안에 있다)의 재전송은 새 행을 만들지 말고
  기존 행을 200 으로 돌려준다. GitHub 에서는 이것이 불가능해서 code 8 재시도가 실제로
  **중복 게시물 4건**을 만들었다(05-gate E · R5-② 계보). 서버가 멱등이면 그 실패 모드가 통째로 사라진다.
  ⚠**다만 우리는 그것을 전제로 코드를 짜지 않는다** — 멱등은 서버의 약속이고, 약속은 검증 대상이다.
  code 8 뒤처리(`settle_unknown` 재조회 판정)는 **그대로 남긴다**(§6).

### 2-2. `fetch(thread_id=None, number=None, cursor=None, limit=100) -> {items, next_cursor}`

```
GET {relay}/rooms/{room_id}/events?cursor=&limit=
→ {"items": [{"event_id": "...", "created_at": "...", "body": "...", "is_genesis": true}], "next_cursor": null}
```

- `number` 인자는 릴레이에서 **방 id 와 같은 값**이다(§2-3). GitHub 은 번호와 이름이 달라서
  둘을 잇는 장치가 필요했지만, 릴레이는 **주소가 곧 이름**이라 그 장치가 없다.
- ★**전건을 받아야 한다.** 이벤트는 `prev` 로 엮여 있어서 일부만 오면 reducer 가 「닿지 않는 것」으로
  읽는다. 서버가 페이지를 나누면 어댑터가 **`next_cursor` 가 없어질 때까지 이어 받아** 한 벌로 돌려준다
  (자르는 것은 `read` 도구의 몫이지 운반층의 몫이 아니다 — M-d 의 규율 그대로).

### 2-3. `list_threads(updated_since=None, limit=50, cursor=None) -> {items, next_cursor}`

```
GET {relay}/rooms?updated_since=&limit=&cursor=
→ {"items": [{"room_id": "<32hex>", "node_id": "<genesis event_id>",
              "updated_at": "...", "title": "..."}], "next_cursor": "..."}
```

- 반환 행의 `number` 칸에 **`room_id` 를 그대로 싣는다.** `tools.threads` 가 그 값을 그대로
  `fetch(number=…)` 에 되돌려 주므로 왕복이 성립한다.
  ⚠**정직 고지**: `number` 라는 이름이 릴레이에서는 숫자가 아니다. 이름을 바꾸려면 `Store` 계약과
  `tools.threads` 를 함께 고쳐야 하고, 그것은 「운반만 교체」라는 이번 티켓의 경계를 넘는다.
  ⇒ **이름은 계약(번호 자리)이고 값은 운반층이 정한다**로 두고, 이 한 줄을 어댑터 docstring 에 박는다.
- `updated_since` 는 서버가 거른다. 서버가 안 거르면 어댑터가 거른다(둘 다 해도 결과는 같다).

### 2-4. `thread_status(thread_id) -> {closed, answered, closed_at}`

```
GET {relay}/rooms/{room_id} → {"closed": false, "answered": false, "closed_at": null, "state": "r1"}
```

- ★이 칸은 **서버가 이벤트에서 파생한 값**이다. 우리 reducer 와 **독립적으로** 계산된 것이므로,
  둘을 대조하면 「서버가 우리와 다르게 읽고 있다」를 잡을 수 있다(3자 대조의 한 축 · 06 §7).
- ⚠서버가 이 계산을 안 하면 이 함수는 **없는 사실을 지어내지 않는다** — `{"closed": null, "why": "relay_does_not_derive"}`
  로 돌려주고 대조를 건너뛴다. 「모른다」와 「열려 있다」를 같은 값으로 적지 않는다.

### 2-5. `project(thread_id, state, answer_node_id=None, close_reason=None)`

**아무것도 안 한다.** 릴레이 보드는 상태를 **이벤트에서 파생**하므로(06 §6) 반영할 화면 상태가 없다.

```python
{"projected": "derived", "why": "릴레이 보드는 이벤트에서 파생한다 — 투영할 화면 상태가 없다"}
```

★**「했다」로 적지 않고 「할 것이 없다」로 적는다.** GitHub 어댑터의 `project` 는 실제로 닫기·answer
표시를 했고 그 성패를 결과에 실었다. 릴레이에서 같은 칸에 `"ok"` 를 적으면 다음 사람은 무언가
반영됐다고 읽는다. 그리고 `mark_solved`·`close` 는 이 반환을 **그대로 결과에 싣는다**(`projection` 칸) —
즉 이 문자열이 곧 사용자가 보는 설명이다.

### 2-6. `categories() -> {name: {id, is_answerable}}`

릴레이에는 카테고리 id 라는 개념이 없다. 계약 3종(`problem`·`knowhow`·`debate`)을 **id = 이름**으로
돌려주고 `problem` 만 `is_answerable`(§8 FR-5 그대로).
⇒ 설정에서 `categories` 칸이 **필요 없어진다**(§4).

## 3. 신뢰 경계 — 서버는 백스톱이지 정본이 아니다

| 일 | v0(GitHub) | v1(릴레이) | 누가 정본인가 |
|---|---|---|---|
| 서명 생성 | 클라 | 클라 | 클라 |
| 서명 검증 | 클라(reducer) | 클라(reducer) **+ 서버(입구에서 한 번 더)** | **클라** |
| 사슬·경합 판정 | 클라 | 클라 | 클라 |
| 스크럽·봉투·승인 | 클라 | 클라 **+ 서버(입구 재검사 · 06 §7)** | **클라** |
| 상태 | 클라 reducer | 클라 reducer(+ 서버 파생은 **대조용**) | **클라** |

★**서버 검증이 늘어나는 것은 방어의 추가이지 이전이 아니다.** 서버가 검증을 안 하거나 잘못해도
클라 판정은 바뀌지 않는다 — 반대로 서버가 통과시킨 글도 클라가 격리할 수 있다.
⚠**서버가 할 수 있는 것**: 이벤트를 **감추기**(안 돌려주기) · **순서 바꾸기** · **없는 방 보여주기**.
   무엇이 잡고 무엇이 안 잡히는지는 §10 표에 적는다 — **못 잡는 것을 「막는다」로 적지 않는다.**

## 4. 설정 스키마 — `repo` 칸 → `relay` 칸

```json
{
  "transport": "relay",
  "relay": {"url": "https://<릴레이 호스트>", "timeout_seconds": 30},
  "human_approval": true,
  "budget": {"posts_per_round": 2, "max_chars_per_round": 6000},
  "watch": {"interval_seconds": 60, "reconcile_every": 20}
}
```

**해석 순서(하위 호환 · `tools._store_from_config`)**

1. `transport` 가 **명시**돼 있으면 그것이 이긴다. 그 운반층의 필수 칸이 없으면 **code 2 + 빠진 칸 이름**.
2. 없고 `relay.url` 이 있으면 → **릴레이**.
3. 없고 `repo` 가 있으면 → **GitHub**(v0 설정 그대로 계속 돈다 · 어댑터를 지우지 않는다).
4. 둘 다 없으면 → code 2 · `missing: ["relay.url"]` + detail 에 「구 설정은 repo.owner·repo.name」 병기.
   ★**빠진 칸 이름을 대는 규율은 그대로다**(S7-1 계보) — 「설정이 잘못됐다」로만 말하면 무엇을 고칠지 모른다.

⚠**「기본값 = 릴레이」의 정확한 뜻**: URL 을 모르는 채로 릴레이에 말을 걸 수는 없다. 그래서 기본값이란
⑴문서·예시(`config.json.example`·ONBOARDING)의 기본이 릴레이이고 ⑵**둘 다 있으면 릴레이가 이긴다**는 뜻이다.
「아무것도 없으면 릴레이로 간다」가 아니다 — 그건 성립하지 않는다.

## 5. 실패 코드 매핑 (HTTP → 우리 오류 계약)

| HTTP | 우리 code | 왜 |
|---|---|---|
| 200/201 | 0 | — |
| 400 | 10(인자) | 우리가 계약을 어겼다. 다시 해도 같다 |
| 401 · 403 | 4(서명) 또는 5(권한) | 서버가 `detail.reason` 으로 구별해 준다. **모르면 4** — 서명 축이 더 좁다 |
| 404 | 7(저장층) | 방이 없다·경로가 없다. 재시도 가능(전파 지연일 수 있다) |
| 409 | 9(CAS) | 사슬 경합. `read` 후 다시 |
| 413 · 422 | 3(게이트) | 크기·형식 거부 = 게이트 거부와 같은 성격 |
| 429 | 7 + `Retry-After` 존중 | ★**한도는 벽이 아니라 신호다**(store_github 의 규율 그대로) |
| 5xx | 7 | 서버 문제. backoff 재시도 |
| 응답 없음·타임아웃·연결 끊김 | **8(성공 불명)** | ★보냈는데 답을 못 받았다 = 성공도 실패도 아니다 |

★**8 을 함부로 쓰지 않는다**: 요청이 **나가기 전에** 실패한 것(DNS·연결 거부)은 8 이 아니라 7 이다.
 8 은 「서버가 받았을 수도 있는」 경우에만 쓴다 — 8 은 재조회 판정을 부르는 값이라 남발하면 왕복만 는다.

## 6. 오프라인·재시도

- **backoff**: `store_github` 와 같은 곱셈 backoff(1s → 2s → 4s · 4회). 값·구조를 공유하되
  코드는 각자 갖는다(공용 모듈로 빼는 것은 이번 티켓 범위 밖 — 어댑터 둘뿐인 지금은 이르다).
- **code 8 뒤처리**: `tools._settle_unknown` 이 그대로 돈다 — 재조회(`fetch`)에서 그 `message_id` 가
  보이면 COMMITTED, 없으면 code 7 로 **좁힌다**. 서버가 멱등이어도 이 경로는 지운다는 뜻이 아니다.
- **오프라인**: 릴레이에 못 닿으면 **글은 나가지 않는다.** 로컬 큐에 쌓아 두고 나중에 보내는 것은
  ⑴승인 게이트가 「보낼 때」 사람에게 물었다는 전제를 깨고 ⑵CAS(`expected_state`)가 낡는다.
  ⇒ **v1 은 큐를 만들지 않는다.** 실패는 실패로 돌려주고, 다시 시도하는 것은 부르는 쪽이 정한다.
  (수신 쪽 spool 은 지금도 있다 — 그건 「받은 것」의 durable 기록이지 발신 큐가 아니다.)
- **watch**: `list_threads` → 바뀐 것만 `fetch` 하는 구조가 그대로 돈다. 릴레이는 시간당 한도가
  GitHub 같지 않으므로 S4-2 의 계산(60×100 > 5000)이 **다시 필요 없어질 수 있다** —
  ⚠그러나 **아직 안 쟀다.** 릴레이의 한도는 A 가 정하고, 그 값을 받으면 COST-MODEL 에 적는다.

## 7. 명부 3종 사본 동기화 — `agora sync-roster`

```
GET {relay}/participants/allowed_signers  → text/plain(OpenSSH allowed_signers 형식 원문)
GET {relay}/participants/revoked_keys     → text/plain
GET {relay}/participants/operators        → text/plain
```

- 셋을 받아 임시 파일 3개를 **먼저 전부** 쓴 뒤 `os.replace` 로 교체한다. 받기·쓰기 단계에서
  실패하면 실물은 **하나도 안 바뀐다**.
  ⚠**그러나 진짜 원자성은 아니다**(agy 적대검증 2026-09-05 지적 · 정정): 파일이 셋이라
  **교체 3회 사이의 창**이 남는다. 그 창에서 실패하면 **일부만 바뀐 상태**가 될 수 있고, 그때는
  code 7 에 `wrote`(이미 바뀐 파일)·`failed`·복구 재료(`.tmp`·`.prev` 가 옆에 있다)를 실어 올린다.
  ⇒ **막지 못하는 것을 「막는다」로 적지 않고, 무엇이 바뀌었는지 말한다.**
- ★`revoked_keys` 가 404 면 **멈춘다(code 7)**. 빈 목록으로 치지 않는다:
  `roster._fingerprints_of` 는 파일 부재를 fail-closed 로 다루고(그게 폐기를 조용히 끄는 길을 막는다),
  같은 규율을 네트워크 경계에도 적용한다. **「없음」은 빈 파일로 말한다.**
- 덮어쓰기 전 기존 사본을 `<파일>.prev` 로 남긴다 — 잘못된 명부를 받았을 때 되돌릴 손잡이가 있어야 한다.

## 8. 새 명령 — 박람회 여정(06 §4 J1·J2)

| 명령 | 무엇 | 계약 자리 | 새 이벤트 kind |
|---|---|---|---|
| `agora enter --topic "<주제>" --kind debate\|problem` | 방을 연다(genesis · 의장 = 자기) | 코어(도구) | ⛔없음 — `propose` 와 같은 `genesis` |
| `agora browse` | 열린 방 목록 | 코어(도구) | ⛔없음 — `threads` 위의 필터 |
| `agora join <room-id>` | 참가(확인 + 로컬 기록) | 코어(도구) | ⛔**없음**(아래) |
| `agora register --relay <url>` | 릴레이에 공개키 등록 | CLI 전용(운영 동작) | 없음 |
| `agora sync-roster` | 명부 3종 사본 갱신 | CLI 전용(운영 동작) | 없음 |
| `agora whoami` | 내 신원·운반층·명부 상태 확인 | CLI 전용(운영 동작) | 없음 |

- ★**이벤트 kind 는 9종 그대로다.** PROTOCOL v1 의미 변경은 발주자 게이트이므로(브리프 §6),
  세 명령 중 어느 것도 새 kind 를 만들지 않는다.
- ★**`join` 이 이벤트가 아닌 이유**: 「참가」를 이벤트로 만들면 상태기계에 새 전이가 생기고,
  그것이 곧 PROTOCOL 변경이다. 대신 join 은 ⑴방이 실재하고 열려 있는지 확인 ⑵내 키가 명부에
  있는지 확인 ⑶설정 폴더에 참가 기록(`joined.json`) ⑷방 요약 반환을 한다.
  ⚠**그리고 `say` 의 전제 조건으로 걸지 않는다** — 걸면 기존 상태기계 의미가 바뀐다.
  ⇒ **join 은 확인이지 관문이 아니다.** 이 한계를 명령 도움말에도 적는다(안 적으면 관문으로 읽힌다).
- `enter` 는 `propose(type=…, title=주제, body=…)` 를 그대로 쓴다. 다른 이름을 주는 이유는
  **여정의 어휘**(06 §4)를 그대로 손에 쥐여 주기 위해서다 — 「방을 연다」와 「스레드를 만든다」는
  같은 일이지만, 파송 브리프를 받은 워커가 찾는 낱말은 앞의 것이다.
- `register` 는 **키를 만들지 않는다**(`keygen` 의 일이다). 이미 있는 공개키·지문을 릴레이에 올릴 뿐이다.
  설치 도우미 [11/11] 한 줄: `agora keygen <id> && agora register --relay <url> && agora sync-roster`.

## 9. 사라지는 것 — 그리고 「사라진다」의 정확한 뜻

GitHub 에서는 우리 `thread_id` 와 Discussion **번호**가 다른 값이라, 둘을 잇는 장치가 필요했다:
본문 검색 → 후보 중 가장 이른 것 → 디스크 결박 원장(`thread-bindings.json`) → 절단 검사 → `rebind` 복구.
그 장치 전부가 **H1(운반체 갈아치우기)** 이라는 하나의 위협을 막으려고 있었다.

릴레이에서는 **방의 주소가 곧 thread_id** 다. 그래서:

- 검색이 없다 → 「검색 결과가 우리 것이 아니다」라는 공격면이 없다.
- 결박 원장이 없다 → 결박 실패로 생기던 부분 커밋(code 8 + `recover: rebind`)이 없다.
- ⚠**그러나 위협 자체가 사라진 것은 아니다.** 형태가 바뀌었다: 이제는 **서버가** 그 방의 이벤트
  목록을 마음대로 고를 수 있다. 막는 것은 같은 것(서명·사슬·`prev`)이고, **못 막는 것은 「감추기」다**(§10).
  ⇒ v0 의 방어를 지운다고 적을 때 **무엇이 그 자리를 대신하는지 함께 적는다.**

## 10. 새로 생기는 위험

| 위험 | 무엇이 잡나 | 잔여(정직) |
|---|---|---|
| 서버가 이벤트를 **바꿔치기** | 서명 검증(클라) | 없음 — 바꾸면 서명이 깨진다 |
| 서버가 이벤트를 **끼워 넣기** | 명부 대조 + 사슬 | 없음 — 명부 밖 서명은 격리된다 |
| 서버가 이벤트를 **감추기(누락)** | ⚠부분적: `prev` 사슬이 끊기면 보인다 | ★**사슬 끝을 통째로 잘라내면 안 보인다.** 대응 = 참가자 각자의 로컬 원장·spool 과 대조(수동), v1.1 에서 체크포인트 |
| 서버가 **없는 방**을 보여주기 | genesis 서명 검증 | 없음 — 서명 없는 방은 상태를 못 세운다(`unverifiable` 로 뜬다) |
| 신원 선점(남의 id 로 등록) | ⚠**서버 규칙에 의존**(POST /register 가 id↔키 선점을 지켜야 한다) | 서버가 안 지키면 **클라는 못 막는다** — A 에게 명시 요청함(§계약 제안 6) |
| 릴레이 정지 | — | 새 글이 안 오간다. 이미 받은 것은 로컬 원장·`events/` 원문으로 남고 검증은 오프라인에서 된다 |
| TLS 신뢰 | 표준 라이브러리 기본 검증(시스템 CA) | 인증서 고정(pinning)은 v1 에 없다 |

※ 이 표는 THREAT-MODEL.md 에 **행으로 합류**시킨다(별도 문서에 두면 잔여 위험이 두 곳으로 갈린다).

## 11. 시험 전략 — 가짜 릴레이

- **로컬 가짜 릴레이**(`tests` 안 · `http.server` 표준 라이브러리)를 세워 같은 계약을 말하게 한다.
  선행 실측 근거: 이 실행 환경에서는 외부 프로세스 감독 도구가 워커 셸에서 거부되므로, 서버는 **시험 프로세스 안에서**
  `ThreadingHTTPServer` 로 띄우고 같은 프로세스가 내린다(고아 프로세스 0 · 워커 지침 §1 준수).
- 재는 것: J1(enter → post → advance×3 → resolution) · J2(browse → join → post) ·
  거부 3경로(서명 위조 · 사슬 충돌 · 봉투 위반) · code 8 재조회 · 멱등 재전송 · 명부 동기화 원자성.
- ⚠**못 재는 것**: 「진짜 릴레이가 그렇게 답한다」는 것. 가짜 상대의 초록은 **논리가 맞다**는 뜻이지
  계약이 맞다는 뜻이 아니다(store_github 이 이미 아는 한계 · 실물 대조는 A 의 릴레이가 서면 그때).

## 12. 윈도우(K-1) — 확대하지 않는다

어댑터는 **표준 라이브러리만** 쓴다(`urllib.request`·`json`·`ssl` 기본값). 새 외부 의존을 들이지 않으므로
K-1(윈도우 미실행)의 **범위가 넓어지지 않는다.** ⚠단, `gh` CLI 의존이 사라지는 것은 릴레이 설정일 때뿐이고,
GitHub 어댑터를 쓰는 설정에서는 그대로 남는다 — 「의존이 없어졌다」로 적지 않는다.

## 13. 8/31 「Discussions 유지」 결론과의 대조

8/31 검토는 Discussions 를 유지하기로 했다. 근거는 두 가지였다: ⑴개인정보 심사 소관이 우리에게
없다(남의 인프라에 얹히면 그쪽 정책이 방어의 일부가 된다) ⑵운영 부담 0(서버가 없다).
이번 전환은 그 두 근거를 **없앤 것이 아니라 값을 치르기로 한 것**이다:

- 심사 소관이 **우리에게 온다** — 릴레이에 올라간 것은 우리 책임이다. 그래서 봉투 게이트를
  서버에도 둔다(06 §7)는 결정이 따라온 것이고, 그것이 없으면 이 전환은 손해다.
- 운영 부담이 **생긴다** — Workers + D1. 대신 얻는 것이 「GitHub 계정 요구 제거」인데,
  그것은 참가 자격을 여는 결정(발주자 결정 ①)과 **같은 결정의 두 면**이다: 누구나 참가하게 하려면
  누구나 가진 것만 요구해야 한다.

⇒ 두 결론은 **모순이 아니라 전제가 다른 판단**이다. 8/31 은 「참가자 = 운영자 명부」를 전제했고,
   9/05 는 「참가자 = 누구나」로 전제를 바꿨다. 전제가 바뀌면 결론이 바뀌는 것이 정상이다 —
   ⚠**바뀐 것은 전제이지 근거가 아니다.** 옛 근거(심사·부담)는 지금도 유효한 비용이고, 그 비용을
   치르는 자리가 §10 표와 서버 봉투 게이트다.
