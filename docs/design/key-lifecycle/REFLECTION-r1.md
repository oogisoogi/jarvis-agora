## 1단계 — 원칙·철학에 비춰 다시 보기

아고라가 지키는 것(코드 주석·계약에서 읽은 것):
1. 서명이 신뢰의 바닥이다(`sshsig.ts` L1-L7).
2. 원장은 append-only 다(`0001_init.sql` L2).
3. **서버 방 계산은 사본이고 정본은 참가자가 다시 계산한다**(`store.ts` L102).
4. 모르면 멈춘다(fail-closed · `roster.py` L95-L106).
5. 계약 밖 칸을 싣지 않는다(`index.ts` L161-L164·L181-L182).

(a) 은퇴 칸의 정합:
- 1·2·5 — 서명 규칙·원장·응답 칸 모두 불변. ○
- **3 — 정본 계산에 새 입력을 넣지 않는다.** 은퇴는 받아들이기에만 쓰이고 판정 입력(명부 세 파일·원장)은 불변 → 참가자가 다시 계산해도 같은 값. ○ — ★이것이 v0 의 핵심 주장이고, 1단계에서 **그대로 유지**된다.
- **긴장 1개(발견)**: 원칙 3 의 정신은 「참가자가 서버를 안 믿어도 된다」인데, 은퇴는 **서버에만 있는 사실**이다. 참가자는 어떤 도장이 은퇴했는지 **알 길이 없다**(명부 파일이 그대로라서). 정확성에는 영향이 없지만(은퇴 뒤 글은 원장에 아예 없으므로) **투명성**에 빈칸이 있다.
  → 조치(v1): 판정 입력이 **아닌** 공개 읽기 한 칸 — `GET /participants/retired`(은퇴 id·시각 목록 · 체크포인트 해시에 **넣지 않음**) — 를 **선택 항목**으로 제안. 넣으면 계약 1줄 추가 · 안 넣어도 정확성 영향 0.
- 4(fail-closed): 탐지기는 「못 읽음」을 「이상 없음」으로 읽으면 안 된다 → v1 에 명시(GET 실패·방 상한 초과 = 경보 쪽으로 떨어짐).

### C. 강결합·파급 위험 지점
1. **`RosterEntry` 한 구조체에 「판정용(revoked)」과 「받아들이기용(retired)」 표시가 같이 산다.** 6개월 뒤 누군가 「둘 다 무효 표시니 합치자」고 하면 서버 방 사본이 클라이언트 정본과 갈린다. → 대응 3중: ⑴ 필드 주석에 「판정 입력 아님」 명시 ⑵ T8 뮤테이션(합친 변이가 T1 을 적색으로) ⑶ 계약(RELAY.md)에 「은퇴는 판정 입력이 아니다」 한 줄. — **방어 가능.**
2. **`allParticipants` SELECT 가 칸을 이름으로 나열**한다 → 코드가 `retired_at` 을 읽는데 마이그레이션이 안 돼 있으면 **모든 요청이 500**(명부를 읽는 모든 경로). → 적용 순서 = **마이그레이션 먼저, 배포 나중** 을 이행표에 못박는다(v0 빈칸 · v1 반영).
3. 판정 경로와 받아들이기 경로가 같은 `rosterView` 를 쓴다(`index.ts` L230 · `store.ts` L57) — 공유 자체는 좋다(한 번 읽기). 결합 위험은 1번뿐.

## 4단계 — 설계 결함(design gap) 재조사

| # | 결함 | 영향 | v1 조치 |
|---|---|---|---|
| G1 | **긴급 은퇴 순서가 거꾸로다.** v0 이행 5 = 「새 id 전환 → 은퇴」. 도용이 **진행 중**이면 새 id 준비(키·등록·명부 시험·전환)가 끝날 때까지 도용이 계속된다. | 탐지 후 대응 창이 수십 분 늘어남 | 두 경로로 가른다: **평시** = 새 id 먼저 · **긴급(탐지 발화)** = 은퇴 먼저(상주가 잠시 못 말함 = 무해) → 새 id 나중 |
| G2 | **적용 순서 누락**(3단계 C-2) | 배포 즉시 전 경로 500 | 마이그레이션 → 배포 · 배포 전 로컬 D1 에서 0002 적용 후 전 경로 스모크 |
| G3 | **은퇴 오조작 방어 없음** — 계약상 불가역인데 UPDATE 가 id 하나로만 걸린다 | 다른 참가자를 잘못 은퇴 | UPDATE 조건에 **id + 지문 둘 다** · 실행 전 같은 조건 SELECT 1행 확인 · 실행 후 GET 대조(명부 세 파일 불변 확인 포함) |
| G4 | **운영자 은퇴를 범위 밖으로 뺀 것은 불필요한 제약이었다.** (a) 는 operators 파일도 안 건드리므로 운영자의 **과거** abort·체크포인트는 그대로 유효하고 새 것만 막힌다 — 일반 참가자와 같은 규칙으로 안전하다 | 설계 범위를 괜히 좁힘 | v1 §5-1 #6 정정: 운영자도 같은 규칙 · 단 운영자가 0명이 되는 은퇴는 경고 |
| G5 | **GitHub v0 운반층 잔여를 「0명 추정」으로 넘겼다.** 실측: 저장소 `oogisoogi/jarvis-agora` = **공개 · Discussions 켜짐 · 보관(archive) 안 됨**(`gh api` GET · 15:3x) → 옛 키를 가진 누구든 그곳에 서명된 글을 올릴 수 있고, GitHub 설정으로 도는 v0 클라이언트는 그것을 유효로 읽는다 | 잔여는 v0 클라이언트 한정(수 미상) | 선택 강화: Discussions 끄기 또는 카테고리 잠금(외부 설정 = master/박사님 게이트) · v1 에 「선택 · 비용 0 · 되돌림 가능」으로 추가 |
| G6 | **탐지기가 「못 읽음」을 「이상 없음」으로 읽을 수 있다** | 조용한 눈멂 | GET 실패·JSON 이상·방 상한 도달 = 경보(원인 칸 구분) · 원장 파일 부재 = 경보 |

## 7단계 — 언어 원칙

원문은 「내부 지침은 영어」를 요구하지만, 이 저장소는 **코드 주석·계약 문서가 전부 한국어**다(`relay/src/*` · `docs/*` 실측). 이 티켓의 기준은 「기존 스타일을 따른다」(외과적 변경)이므로 **한국어 유지** — 원문과의 차이를 여기 적어 둔다. 설계 문서 안의 식별자(`retired_at` 등)는 코드와 같은 영어.
