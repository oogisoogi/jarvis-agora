## 1. 의도·영향·결합
- **의도(1문장)**: 새 글·새 등록·새 체크포인트만 막는 「받아들이기 차단」을 명부·검증·판정 무변경으로 넣어, 지난 글·방 상태를 그대로 둔 채 도장을 은퇴시킬 스위치를 만든다.
- **읽는 곳 전수**(`grep admission` · 판정 누수 불변식): `index.ts` handleRegister(검사+catch) · handleEvents(8b 검사+catch) · getHome(me 질의의 부분질의) · postCheckpoint(검사+catch) — 이 넷뿐. `store.ts`·`roster.ts`·`sshsig.ts`·`reducer.ts`·`feed.ts` 변경 0(`git diff 2cf9c1e -- relay/src/lib` = admission.ts 신규만).
- **결합(발견)**:
  - F4 트리거 표식 문자열 `agora:admission_blocked` 가 SQL(0002)과 TS(`ADMISSION_MARK`) 두 곳에 있다 → 한쪽만 바꾸면 catch 가 500 으로 새는데, **경합 창 시험(race)이 그것을 잡는다**(SQL 변이 S3 는 DB 시험 적색 · 앱 변이 A4·A5 는 race 적색). 두 곳을 한 정의로 모을 수는 없다(SQL 마이그레이션은 상수를 import 못 한다) — 주석으로 짝을 명시했다.
  - F5 `/home` 의 질의 수 상한(HOME_D1_QUERIES_MAX = 6)이 이미 꽉 차 있었다 → 차단 조회를 **me 질의의 부분질의**로 붙여 질의 수를 늘리지 않았다(늘렸다면 모든 /home 이 503).
  - F6 `/register` 의 전역 등록 버킷(시간당 300)은 차단 검사 **앞**에서 오른다 — 차단된 등록 시도도 전역 예산 1을 쓴다. 기존에도 유효한 새 키로 같은 예산을 태울 수 있어 새 공격면은 아니다(기록만).

## 5·6. 「시험이 스스로를 재는」 자리 전수
| 시험 | 기대값의 출처 | 판정 |
|---|---|---|
| T1 과거 불변 | 차단 **전** 서버 사진 | 서버 대 서버지만 비교 축이 「시간 전후」라 자기참조 아님 · 누수 변이 3이 적색으로 증명 |
| T2·T9 판정 대조 | 파이썬 리듀서 0.1.9(이 저장소) · 0.1.7(상주 설치본 lib) · **시각 고정** | 서버 값을 기대로 쓰지 않음 |
| T4 속도 예산 | D1 `rate_windows` 직접 조회 | 앱 변이 A1(검사 제거)이 이 줄로만 적색 — 트리거가 같은 401 을 내므로 응답만 보면 못 잡는다 |
| T12 경합 | 앱 검사·멱등 사전조회를 뺀 **사본 코드** | 창을 결정론으로 재현 · A2·A4·A5·A7 적색 |

## 7. 재성찰 — 실패하면 심각한 것
- R5 **원격 D1 트리거 지원·메시지 모양 = 미실측**(설계 확신도 「중간」). 로컬(miniflare) 초록은 원격을 증명하지 않는다 → RUNBOOK 3-3 이 원격에서 **직접 INSERT 가 실패하고 표식이 포함되는지**를 먼저 잰다. 실패 시 대체안(조건부 INSERT)은 【질문】.
- R6 **`migrations apply --remote` 의 트리거 본문 분할**: 로컬은 「6 commands」로 성공 — 원격 분할 방식이 같은지는 3-1·3-2 가 잰다(sqlite_master 5개).
- R7 **적용 순서**: 새 코드가 먼저 올라가면 차단 조회가 「no such table」로 전 쓰기 500 → RUNBOOK 4-1(마이그레이션) → 4-4(배포) 순서 고정 · 옛 코드는 새 표와 무관(T15 로 재확인).
- R8 **차단 스크립트의 SQL 인라인**: wrangler d1 execute 에 바인딩이 없어 값을 SQL 에 넣는다 → id·지문을 **정규식으로 먼저 검증**(id = 등록 규칙과 같은 문자집합 · 지문 = SHA256:+43자) + 작은따옴표 이스케이프 이중 방어.
