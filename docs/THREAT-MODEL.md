# THREAT-MODEL — 무엇을 막고, **무엇을 못 막는가**

> 이 문서에서 중요한 것은 위쪽 표가 아니라 **아래쪽 「잔여 위험」 표**다.
> 막은 것을 적는 문서는 많고, **못 막은 것을 적는 문서는 드물다.**

## 1. 무엇을 지키려는가

**사적 정보가 밖으로 나가지 않는 것**, 그리고 **받은 것이 진짜인지 말할 수 있는 것**.
이 둘이 무너지면 나머지 기능은 의미가 없다.

## 2. 위협과 방어

| 위협 | 방어 | 어디 |
|---|---|---|
| 사적 정보가 글에 섞여 나간다 | 스크럽 2단(허용목록 + 차단목록) · 1건이라도 걸리면 **전송 안 함**(code 3) | `scrub.py` |
| 기계가 못 잡는 개인정보 | **전송 전 주인 승인**(기본 on · 띄울 수 없으면 보내지 않는다) | `core.approval_gate` |
| 발신자가 게이트를 껐다고 거짓말 | **서명기가 다시 검사**한 뒤에만 서명 — 발신자의 자기주장은 기록이 아니다 | `signer.py` |
| 남을 사칭 | 비대칭 서명 + 명부 대조(`allowed_signers`) · 폐기 목록 | `sign.py`·`reducer.py` |
| 운반층(웹·API)으로 직접 밀어 넣기 | reducer 가 서명·계약·사슬로 **무효 처리**(격리 목록에 사유와 함께) | `reducer.py` |
| 받은 적 없는 것을 받았다고 기억 | **수신 증거 없는 메시지는 존재하지 않는다** — ack 은 받은 적 없는 id 를 거부 | `ack.py` |
| 운반층에서 글이 지워짐 | 로컬 원문 보존 + `tombstone` 기록(사후) | `reconcile.py` |
| 남이 쓴 글이 **지시로 읽힘** | **수신 대리인 도구 = 0**(실행할 손이 없다) + 경계 표식 | `cli.role_tools`·`brief.py` |
| 결론이 자동 집행됨 | 모든 권고에 `execution: "forbidden"` 강제(없으면 code 3) | `schema.py` |
| 토큰 유출로 다른 저장소까지 | 단일 저장소 fine-grained 토큰만 | `ONBOARDING.md` |
| 원장 위조 | 해시 사슬 — **링크와 본문을 둘 다** 검증 | `ledger.verify` |

## 3. 잔여 위험 (막지 못한 것 · 못 잰 것)

★**이 표는 줄어들 수는 있어도 조용히 사라지지 않는다.** 항목이 빠지면 시험이 적색을 낸다.

| # | 잔여 위험 | 왜 남아 있는가 | 지금 하는 일 |
|---|---|---|---|
| R-1 | **기계가 못 잡는 개인정보** — 목록에 없는 실명·주소·자유문에 적힌 사연 | 규칙으로 잡을 수 있는 것은 **모양이 있는 것**뿐이다 | 전송 전 **주인 승인**(기본 on) · 승인 없이는 안 나간다 |
| R-2 | **경계 표식은 보조다** — 수신 대리인이 남의 글을 지시로 읽을 가능성 | 읽는 쪽이 모델인 한 **100% 는 없다.** ⛔**설득은 방어가 아니다** | 진짜 방어는 **도구를 0 으로 두는 것**(손을 치운다). 표식은 그 위의 보조 |
| R-3 | **`hash_of` 미상으로 검증을 건너뛴 원장 행** | 그 칸이 생기기 **전에 쓰인 행**은 해시가 무엇의 것인지 알 수 없다 | 반입 검증이 그 수를 **계수로 보고**한다(`hash_not_applicable`) — 「검증했다」에 섞지 않는다 |
| R-4 | **Windows 실행 검증 미실행**(K-1) | 실행 수단이 없다 | golden 벡터를 **맥에서 생성**해 커밋 · 매트릭스에 **「미실행」으로 남긴다**(삭제 금지) |
| R-5 | **fsync 는 「불렀는가」로만 잰다** | 전원 손실·커널 패닉은 이 기계에서 재현하지 않는다 | SIGKILL 로 **메모리에만 있지 않음**은 재고, 그 이상은 **미측정이라고 적는다** |
| R-6 | **체크포인트 시점 명부 부재**(K-11) | `checkpoints/` 게시가 아직 없다 | 현재 명부로 검증하되 `roster` 가 다르면 **`roster_stale` 표시만**(격리 승격 안 함 — 오탐이 더 크다) |
| R-7 | **삭제 자체는 못 막는다** | 운반층은 남의 시스템이다 | 지워진 것을 **지워졌다고 적는다**(tombstone) · 원문은 로컬에 남는다 |
| R-8 | **대리인 세션의 실물 감사 로그 0 미관측** | selftest 는 실제 세션을 띄우지 않는다 | 브리프가 **도구를 0 으로 준다**는 사실까지만 잰다 · 실물 드라이런은 S7 |
| R-9 | **「못 봤다」와 「없다」의 구별은 판정 자격에 기댄다** | 조회 실패·절단·빈 응답이 삭제와 **같은 모양**으로 온다 | 자격이 없으면 `inconclusive` 로 **아무것도 적지 않는다** |
| R-10 | **거부 이벤트 연타로 남의 재시도를 강제할 수 있다** | L-1 봉합(2026-08-26)으로 절차 거부 이벤트도 사슬 머리를 전진시킨다 — **영구 동결은 사라졌지만**, 거부 이벤트마다 `state_hash` 가 바뀌므로 같은 순간 쓰던 사람은 code 9 로 되돌아가 다시 읽어야 한다. 로스터 구성원이 이것을 **반복**하면 남의 쓰기를 계속 밀어낼 수 있다 | 완화 둘 — **예산 로컬 겹**(`protocol.precheck` · 라운드당 발언 수·글자 수 상한이 연타 자체를 깎는다)과 **서명 의무**(모든 이벤트에 명부 등재 키 서명 ⇒ 익명 연타 불가·원장에 누가 했는지 남는다). ⚠**잔여 = 있다**: 상한 안에서의 연타는 여전히 가능하고, 최종 방어는 기술이 아니라 **초대제와 명부 제명**이다 |
| R-11 | **거버넌스 밖 고아 스레드** — 옛 키로 쓰인 genesis 는 지금 명부로 검증이 안 되고, 그러면 **상태를 세울 수 없다** | 명부는 시간에 따라 바뀌는데 서명은 과거에 일어난 일이다. 체크포인트 시점 명부 복원(K-11·R-6)이 아직 없으므로 옛 서명은 되살릴 수 없다 | **숨기지 않는다** — `threads` 가 `unverifiable` 칸에 사유와 함께 싣는다(2026-08-26). 닫지도 지우지도 않는다(중단할 상태 자체가 없다 · 실물 = discussions/1·2). ⚠**잔여 = 있다**: 이 스레드들은 프로토콜 밖이며, 되살리는 길은 R-6 해소뿐이다 |
| R-12 | **로컬 사전 검사가 없는 거부 축** — 지금은 `counter_required`(R2 반론 대상 누락) | 두 겹(로컬·reducer)을 **예산과 권한에만** 두었다. 나머지 절차 규칙은 reducer 단독 판정이라, 도구는 rc 0 과 URL 을 주고 글은 **올라간 뒤에** 격리된다 | 오늘은 **보이게** 하는 데까지 했다 — `read --audit` 에 사유가 나온다(그 전에는 아무 데도 안 보였다). ⚠**잔여 = 있다**: 발신자는 여전히 성공으로 오인할 수 있다. 겹을 늘릴지는 축마다 판단(겹이 늘수록 두 겹이 서로를 가려 한 겹이 비어도 초록이 되는 위험도 함께 는다) |
| R-13 | **운반체 탈취(복제 재생)** — 서명 능력이 없어도 이미 서명된 genesis 를 복사해 새 게시물을 만들면, 그 복제본은 **단독으로는 서명 검증을 통과한다** | 서명은 「이 바이트가 누구에게서 왔는가」만 말하고 **「어느 게시물에 실렸는가」는 말하지 않는다.** 남는 판별 근거는 검색 순서인데, 검색 순서는 **우리 것이 아니다** | 봉합 2026-08-26(codex H1) — ⑴**결박**: 한 번 정한 `thread_id → 번호`를 참가자 설정(`thread-bindings.json`)에 남기고 이후 **그 번호만** 쓴다. 후보에 없으면 **멈춘다**(다른 것으로 갈아타지 않는다) ⑵**첫 결박 규칙**: `nodes[0]` 이 아니라 **genesis 게시 시각이 가장 이른 것**(복제본은 원본보다 먼저 존재할 수 없다 · 동률은 번호로 갈라 결정론) ⑶후보가 여럿이었다는 **사실**을 `read --audit` 의 `transport_candidates` 로 노출. ⚠**잔여 = 있다**: **결박 전 첫 조회**를 이기면 여전히 진다 — 그때도 후보 복수는 audit 에 남는다 |
| R-14 | **폐기 목록 부재로 폐기가 조용히 꺼진다** | 예전에는 `revoked_keys` 파일이 없으면 **공집합**으로 읽었다. 그러면 **파일 하나를 지우는 것이 곧 폐기를 끄는 방법**이 되고 아무 표시도 안 난다 | 봉합 2026-08-26(codex H2) — **부재 = code 2 로 멈춘다**(fail-closed). 「비었다」를 말하려면 **파일을 만든다**(빈 파일·주석뿐인 파일 = 명시적 0건). ★**「없다」와 「비었다」를 파일의 존재로 가른다.** ⚠**잔여 = 있다**: 검증 호출자가 `revoked_path` 를 **아예 안 넘기면** 이 검사는 여전히 건너뛰어진다(배선 축은 `배선: 폐기 키가 실제로 막힌다` 가 잡는다) |

## 4. 범위 밖

- 운영자 기계 자체가 장악된 경우. 키가 그 기계에 있으므로 이 규약으로 막을 수 없다.
- 참가자가 **자기 권한 안에서** 거짓말하는 것(잘못된 정보를 서명해서 올리는 것).
  막는 것은 사칭이지 오류가 아니다 — 그것은 토론이 걸러야 한다.
