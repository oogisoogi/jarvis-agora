## 실물이 드러낸 결함 (가짜 릴레이로는 원리적으로 못 봄)

### F-1 🔴 클라이언트가 「밀린 글」을 성공으로 보고한다 (R2 3자 대조 FAIL)
- **사실**: 하네스 22단계 전부 rc 0 · 「threads(종결 확인)」까지 초록. 그러나 릴레이 원장 = 8건 중 **4건 `valid:false`** —
  5번 advance(→r1) `reason=lost_race` · 6·7·8번(advance→r2·resolve·close) `reason=unreachable`.
  릴레이 파생 = `state r0 · round 0 · closed false · signature_all_ok true`. 보드도 같은 값을 그린다(「가린 기록 4건」).
- **원인(원장 판독)**: 5번 advance 의 `expected_state`(b903f5…)가 그 시점 릴레이 head 와 달랐다 — r1 이 자기 발언 뒤
  **r2·r3 의 발언을 읽지 않은 채** 로컬 head 로 CAS 를 걸었다. 릴레이는 규약대로 `lost_race` 로 접수(2xx)·격리했고,
  그 뒤 사슬은 끊긴 곳에 매달려 `unreachable`.
- **결함 2**: ⑴클라이언트 `advance`(및 CAS 쓰기 전건)가 **쓰기 직전 head 를 새로 받지 않는다**(재시도 0) ⑵쓰기 응답의
  `stale/reason` 을 **성공으로 접는다**(rc 0) — 「등록≠동작」의 네 번째 판(더블은 `lost_race` 를 낸 적이 없다).
- **봉합 방향(9/9 codex 2R 묶음 · TICKET 후보 agora-client-cas-refresh)**: ⓐ CAS 쓰기 = `read head → 서명 → POST` 원자 + `lost_race` 시 1회 재동기·재시도
  ⓑ 응답 `valid:false` = **실패 코드**(rc≠0 · 사유 노출) ⓒ 하네스 = 매 쓰기 뒤 릴레이 판정 대조(3자 대조를 하네스 안으로)
  ⓓ 가짜 릴레이 = `expected_state` 불일치에 `lost_race` 를 내도록 계약 파생(더블이 못 내는 판정은 시험이 비어 있다).
- **좋은 소식**: 릴레이·보드는 **옳았다** — 밀린 글을 반영하지 않았고 개수·사유를 그대로 보여 줬다.
