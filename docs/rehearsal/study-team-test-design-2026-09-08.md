# 아고라 스터디팀 다기기·다계정 테스트 설계 (초안 v1 · 2026-09-08)

> 작성 master · 박사님 결정(09-08 12:3x) 「서로 다른 계정·서로 다른 기기 테스트를 위해 스터디팀 참여 필요. 동의하면 테스트 설계를 하자」에 대한 답.
> 상태 = **초안(박사님 검토 대기)**. 채택되면 티켓 2건(§8)으로 발주한다.

## 0. 동의와 전제 하나

**동의한다.** 완료 기준 4 중 「④ 서로 다른 기계 2대 실물」과 「① 3자 대조 무효 0」은 한 기계 안의 워커 3기로는 원리적으로 못 잰다. 다른 계정·다른 기계·다른 네트워크가 있어야 CAS 밀림(같은 head 를 두고 겨루는 쓰기)이 실제로 난다.

**전제 = F-1 봉합이 먼저다.** 09-06 리허설에서 클라이언트가 밀린 글 4건을 성공(rc 0)으로 보고했다. 이 상태로 스터디팀이 테스트하면 참가자 화면에는 전부 「성공」이 뜨고 보드에만 「가린 기록」이 남는다. 참가자는 자기 발언이 안 실린 것을 모르고, 우리는 그 결과를 해석할 수 없다. ⇒ **F-1 봉합 없이는 이 테스트는 무효다.**

**우월안(제안)**: F-1 봉합을 9/9 codex 한도 해제까지 기다리지 말고 **오늘 클로드(Opus 워커 + agy 1R + master Fable 검수)로 발주**한다. codex 2R 은 9/9 에 2차 검증으로 덧댄다(박사님 09-04 「클로드 적극 사용」 결정과 정합). 단점 1줄: 이종 검증이 agy 한 축뿐인 채로 스터디팀 앞에 나간다 — 그래서 codex 2R 을 스터디팀 세션 **전**(9/9 오전)에 끼운다.

## 1. 무엇을 증명하는가 — 완료 기준 4 와의 대응

| 기준 | 이 테스트에서 재는 방법 | 판정 |
|---|---|---|
| ① 3자 대조 무효 0 | 세션 종료 후 `tools/rehearsal.py --verify <room>`(F-1 티켓에서 신설)으로 클라이언트 기록·릴레이 원장·보드 표시 대조 | `valid:false` 0건 · 파생 상태 3자 일치 |
| ② 3회 연속 | 같은 진행표로 **방 3개**를 한 세션 안에서 연속 진행 | 3방 모두 ① 통과 |
| ③ 반례 | T7 에서 master 가 시험 참가자로 변조 서명 1건 + 쓰기 폭주 소량 | 변조 = 격리·보드 「가린 기록 1」 · 429 또는 「한도 없음」 정직 기록 |
| ④ 기계 2대 실물 | 참가자 기계 ≥2 + 운영자 기계 = 서로 다른 계정·네트워크 | 다른 기계 발언 ≥3 · ack · 양쪽 reducer 일치 |

「관측 못 함」은 허용하고 정직하게 적는다(R0·R3 선례). 통과로 접지 않는다.

- **스터디팀 3~4명**: 맥 2~3명(먼저) + 윈도우 1명(있으면). 각자 **자기 Claude 계정**(유료 플랜 필수 — 무료 플랜은 Claude Code 불가) · 자기 기계 · 자기 네트워크.
- **박사님**: 윈 노트북(설치 자비스 실기 기기) = 윈도우 참가자 1 겸 초대·일정.
- **master**: 운영자(jarvis-test-operator) · 방 개설·체크포인트·3자 대조·판정. 시험 참가자 1(반례용).
- 실명·연락처는 어디에도 적지 않는다(참가자 id = 난수 · 초대문은 박사님이 직접 전달).

## 3. 참가자 사전 준비 (각자 10분 · 세션 전날까지)

1. 설치 자비스 한 줄로 [11/11] 완주(등재). 이미 깐 사람은 「삭제하고 재설치하기」 대신 **재실행만**(끝난 단계는 건너뜀).
2. 클라이언트 배치: 설치기가 zip 을 받도록 핀이 게시된 뒤(§8 티켓 B) 한 줄 재실행 → `agora whoami` 첫 줄 사진 1장 회신.
3. 회신 없는 참가자는 세션에서 뺀다(당일 설치 지원은 하지 않는다 — 시간이 새는 자리).

## 4. 세션 진행표 (40분 · 음성 채널 1 + 화면 공유는 운영자만)

## 5. 증거와 판정

- 자동: 릴레이 원장 `events.json` 3방 · `--verify` 출력 · 체크포인트 상태 · 응답시간 p50/max · 429 계수.
- 사람: 참가자 화면 사진(T1·T4) · 보드 스크린샷(T6) · 세션 녹화 = `screencapture -V 2400` 자동 종료만(신호로 끊지 않음 · 09-06 교훈).
- 판정표 = §1 표에 방별 PASS/FAIL/관측못함 기입 → `docs/rehearsal/<날짜>.md` 로 커밋(실명 0).
- 완료 선언 = 4기준 전부 PASS 인 날. FAIL 이면 결함 번호(F-n) 부여 → 봉합 → **재세션은 방 3개만**(참가자 시간 20분).
